# 人生图谱 Stage 0 原型与技术验证实施计划

**文档版本：** v0.1  
**日期：** 2026-08-05  
**项目阶段：** Stage 0——原型与技术验证  
**上位文档：** 《人生图谱系统初版设计草案 v0.3》  

---

## 1. 阶段目的

Stage 0 的目标不是完成正式产品，而是通过一个最小、可运行、可验证的原型，证明“人生图谱”在产品体验和技术架构上均具备继续开发的可行性。

本阶段重点验证两条主线：

### 1.1 产品体验可行性

验证以下问题：

1. 以 100 岁为默认长度的人生日期格是否直观；
2. 约 36,525 个日期格是否能够流畅展示；
3. 人生、年、月三层视图之间的切换是否自然；
4. 过去、今天、未来三类日期状态是否容易辨认；
5. 事件、记忆和未来计划是否能够清楚挂接到日期；
6. 用户是否愿意通过该界面长期浏览和补充个人记录。

### 1.2 技术底座可行性

验证以下问题：

1. 桌面前端能否完全通过统一 API 访问数据；
2. 本地后端能否使用加密数据库运行；
3. PIN、主密钥和恢复凭据能否正确分层；
4. 仓库锁定后是否无法读取敏感数据；
5. 数据能否整体导出为加密迁移包；
6. 迁移包能否在另一目录或另一设备恢复；
7. 同一套后端是否具备后期部署到 VPS 的基础；
8. 浏览器插件能否安全连接本地 API。

---

## 2. Stage 0 完成判定

只有同时满足以下条件，Stage 0 才算完成：

- 人生总览能够稳定显示完整 100 年日期格；
- 人生、年、月视图可以连续进入和返回；
- 可以创建事件、记忆和未来计划；
- 所有数据操作均通过 `/api/v1` 完成；
- 数据库文件为加密状态；
- PIN 可以解锁，错误 PIN 无法访问；
- 恢复凭据能够在新环境中恢复仓库；
- 可以导出并重新导入 `.lifevault` 迁移包；
- 浏览器插件可以显示生命、年度和月度进度；
- 核心操作具备基础自动化测试；
- 项目可以在一台全新 Windows 电脑上按文档重新运行。

## 4. 推荐技术架构

Stage 0 建议采用以下逻辑架构：

```text
桌面应用外壳
├─ 前端界面
│  ├─ 人生总览
│  ├─ 年/月视图
│  ├─ 日期详情
│  └─ 设置与迁移
│
├─ API 客户端
│
├─ 本地后端服务
│  ├─ 认证与解锁
│  ├─ 进度计算
│  ├─ 事件服务
│  ├─ 记忆服务
│  ├─ 计划服务
│  ├─ 迁移与备份
│  └─ 设备授权
│
├─ 加密数据仓库
│  ├─ 加密 SQLite
│  ├─ 仓库配置
│  └─ 快照与迁移包
│
└─ 浏览器插件
   ├─ 进度展示
   ├─ 快速记录
   └─ 打开主程序
```

### 4.1 推荐实现原则

- 前端不直接访问数据库；
- 前端不保存主密钥；
- 本地 API 默认只监听 `127.0.0.1`；
- 所有 API 均位于 `/api/v1`；
- 所有核心实体使用全局唯一 ID；
- 数据库从创建时开始即加密；
- 日志中不得记录 PIN、密码、主密钥或敏感正文；
- Stage 0 使用单进程或少量进程即可，不提前引入分布式架构。

## 6. 页面原型设计

## 6.1 初始化页面

### 目标

创建第一个加密人生仓库。

### 字段

- 姓名或档案名称；
- 出生日期；
- 目标年龄，默认 100 岁；
- 本机访问 PIN；
- 再次输入 PIN；
- 恢复密码或生成恢复密钥；
- 自动锁定时长；
- 是否显示剩余时间；
- 数据仓库保存位置。

### 初始化流程

```text
填写个人信息
    ↓
设置 PIN
    ↓
设置或生成恢复凭据
    ↓
生成随机主密钥
    ↓
创建加密数据库
    ↓
创建个人档案
    ↓
进入人生总览
```

### 验收标准

- PIN 不一致时不能继续；
- 不记录明文 PIN；
- 成功创建加密仓库；
- 关闭程序后必须重新解锁；
- 恢复信息必须明确提示用户妥善保存。

---

## 6.2 解锁页面

### 内容

- 档案名称；
- PIN 输入；
- 解锁按钮；
- 使用恢复凭据；
- 错误提示；
- 剩余尝试限制或延迟提示。

### 验收标准

- 正确 PIN 可解锁；
- 错误 PIN 无法访问 API 数据；
- 连续错误尝试触发延迟；
- 解锁会话到期后自动返回锁定状态；
- 恢复凭据可以重设本机 PIN。

## 6.3 人生总览页面

### 页面目标

在一个页面中展示完整生命时间、当前进度以及各日期内容状态。

### 推荐布局

```text
┌────────────────────────────────────────────────────┐
│ 姓名  当前年龄  人生第 xxxx 天   人生进度 xx.x%    │
│ [人生] [年] [月]   [公历] [农历] [双历]           │
├────────────────────────────────────────────────────┤
│ 0岁   □□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□ │
│ 1岁   □□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□ │
│ 2岁   □□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□ │
│ ...                                                │
│ 99岁  □□□□□□□□□□□□□□□□□□□□□□□□□□□□□□□ │
├────────────────────────────────────────────────────┤
│ 当前选中日期摘要 / 图例 / 进度信息                 │
└────────────────────────────────────────────────────┘
```

### 原型阶段需要验证

- 每行一年与连续网格两种布局；
- Canvas 与虚拟化 DOM 的性能差异；
- 36,525 个日期格的首屏加载；
- 缩放与滚动体验；
- 鼠标悬停提示；
- 点击进入年、月、日；
- 高 DPI 和系统缩放适配；
- 深色和浅色模式可读性。

### 基础视觉规则

- 已过去：中性实色；
- 今天：高亮描边；
- 未来：浅色或低对比度；
- 有事件：中心圆点；
- 有记忆：柔和边框；
- 有计划：空心标识；
- 多条内容：资料密度加深；
- 无记录的已过去日期仍保留已走过状态。

## 8. 时间表示规范

时间模型必须在 Stage 0 明确，避免后期重构。

### 8.1 日期类型

- 精确日期；
- 精确时间；
- 月份；
- 年份；
- 起止时间段；
- 大约时间；
- 未知时间。

### 8.2 存储原则

- 绝对时间统一使用 ISO 8601；
- 有时区的时间统一保存时区信息或 UTC；
- 纯日期事件不强行转换成 UTC；
- 保存原始输入时区；
- 生命进度依据档案时区计算；
- 农历日期由公历日期动态计算；
- 不重复把农历文本写死为唯一日期来源。

### 8.3 未来兼容

所有核心实体使用全局唯一 ID，并保留：

- `revision`；
- `created_by_device`；
- `updated_by_device`；
- `deleted_at`。

```text

```

- 未初始化；
- 已锁定；
- 已解锁；
- 迁移中；
- 错误。

## 11. 加密仓库验证计划

## 11.1 仓库结构

```text
LifeGraphVault/
├─ vault.json
├─ lifegraph.db
├─ blobs/
├─ thumbnails/
├─ backups/
└─ runtime/
```

## 11.2 Stage 0 必须验证

1. 创建仓库后数据库不可被普通 SQLite 工具直接读取；
2. 正确 PIN 可以解锁；
3. 错误 PIN 无法解锁；
4. 更换 PIN 不需要重新加密全部数据；
5. 恢复凭据可以重设 PIN；
6. 锁定后 API 不返回敏感数据；
7. 自动锁定生效；
8. 迁移包被篡改后无法导入；
9. 迁移包在另一目录可以恢复；
10. 密钥和 PIN 不出现在日志或异常堆栈中。

## 12. PIN、主密钥与恢复凭据

### 12.1 密钥层次

```text
PIN / 恢复凭据
        ↓
密钥派生与包装
        ↓
随机主密钥
        ↓
数据库与仓库数据
```

### 12.2 Stage 0 规则

- PIN 最少 6 位，允许更长数字 PIN；
- 主密钥由安全随机数生成；
- PIN 不直接作为数据库密钥；
- 恢复凭据独立于 PIN；
- PIN 错误尝试需要延迟；
- 主密钥只在解锁期间保存在内存；
- 锁定时清理会话和敏感内存引用；
- 更换 PIN 只重新包装主密钥；
- 恢复操作写入安全审计日志。

### 12.3 Stage 0 恢复方式

建议原型阶段同时验证两种方案：

#### 恢复密码

用户自行设置较长密码。

#### 恢复密钥

系统生成高熵恢复字符串或文件。

验证完成后再决定正式产品是否同时保留两种方式。
