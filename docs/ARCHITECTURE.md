# LifeGraph 当前架构说明（v0.0.4）

```text
浏览器页面
    ↓ REST / JSON / multipart
FastAPI /api/v1
    ↓
VaultManager
    ├─ PIN / 恢复密钥解锁
    ├─ 内存主密钥与会话令牌
    ├─ 个人档案与内容业务规则
    ├─ .lifevault 导出 / 演练 / 恢复
    ├─ 自动备份策略、健康状态与历史管理
    ├─ PIN／恢复密钥槽轮换
    ├─ 密钥槽状态与本地安全审计摘要
    └─ Database
          ↓
SQLite（业务正文为 AES-GCM 密文）
```

## 本地数据布局

```text
data/
├─ vault.json
├─ lifegraph.db
├─ backups/
│  └─ auto/
│     └─ lifegraph-auto-*.lifevault
└─ recovery/
   └─ lifegraph-before-restore-*.lifevault
```

- `vault.json` 保存 KDF 参数、包装后的主密钥、验证密文、密钥槽更新时间、不含秘密的安全审计摘要和自动备份策略；
- `lifegraph.db` 保存结构字段与加密档案、事件、记忆和计划；
- `backups/auto/` 只保存由周期策略管理的本地自动备份；
- `recovery/` 只保存正式恢复前生成的安全回滚包，两类历史互不清理。

## 为什么所有界面都走 API

- 浏览器不直接读取 SQLite 或密钥包装文件；
- 认证、会话、并发校验、备份和恢复规则集中在后端；
- 数据库实现和加密结构可以升级而不直接暴露给客户端；
- 未来浏览器插件或移动端可以复用同一接口。

## 自动备份触发模型

自动备份不是独立云同步服务。启用后，普通 API 活动成功完成时，后端检查每天或每周周期是否到期：

1. 未到期时立即跳过；
2. 到期时生成一致性 SQLite 快照；
3. 验证全部加密记录并写入 `.lifevault`；
4. 重新读取实际落盘字节，验证 ZIP、SHA-256、SQLite、外键和全部密文；
5. 记录最近成功与最近完整验证摘要；
6. 按保留数量删除最旧的自动备份；
7. 失败只记录状态，不回滚已经成功的用户操作。

备份健康状态根据策略是否启用、是否存在可用文件、周期是否超期、最近错误和最近完整验证结果综合计算。前端只接收非敏感摘要。

## 密钥槽与审计模型

PIN 与恢复密钥分别拥有独立盐、AAD 和 Argon2id 包装槽。修改其中一个槽时：

1. 先用当前有效凭据解开并验证同一个仓库主密钥；
2. 只为目标槽生成新的盐、nonce 和包装密文；
3. 不改动另一个槽；
4. 不改动 SQLite 中任何业务密文；
5. 原子写回 `vault.json`；
6. 追加不含秘密的安全动作和时间摘要。

旧版元数据没有审计字段时，读取层会根据仓库创建时间和旧 `security_updated_at` 合成只读摘要，不要求数据库迁移。

## 当前边界

当前版本仍未实现：

- 整库 SQLCipher；
- 操作系统安全凭据存储；
- 云端同步和多设备冲突合并；
- 图片与附件；
- 插件设备配对；
- 第三方安全审计。
