## 发布结论

v0.0.9 已完成“大文件与影音资料”阶段，并达到稳定发布、归档、Git commit 与 `v0.0.9` tag 条件。

## 核心验收

- [x] ≤50 MB 普通资料继续使用 `blob-v1`，原有资料系统无回归；
- [x] GB / 数十 GB 文件使用 `chunked-v1` 分块加密，不整文件进入内存；
- [x] 分块上传支持暂停、继续、取消、失败恢复和刷新后断点续传；
- [x] 大文件重复检测有效；
- [x] 6.56 GB MKV 实机上传与入库正常；
- [x] 视频时长、分辨率、编码和加密封面正常；
- [x] HTTP Range / 206 播放、拖动定位和流式下载正常；
- [x] DTS / AC-3 等浏览器不兼容音轨可生成 MP3/AAC 兼容轨并正常出声；
- [x] 原视频、原始音轨不修改；
- [x] `.lifevault v3` 不包含大型原始媒体，大小主要随普通附件增长；
- [x] 恢复核心备份后支持大型媒体离线状态和自动重新挂接；
- [x] 大型媒体可独立增量备份到本地/外置盘；
- [x] 未变化分块再次备份时跳过；
- [x] 支持原始媒体深度校验和媒体备份完整校验；
- [x] 登录与资料中心不再因历史 `.lifevault` 扫描明显变慢；
- [x] 大视频长时间 Range 播放正常。

## 安全边界

- 每个大型媒体块独立 AES-GCM 认证；
- Range 只在内存中生成必要明文块；
- 64 MB LRU 明文块缓存不落盘，锁仓/恢复时清空；
- 媒体备份仍保存密文块，不生成明文媒体镜像；
- `data/audio_compat` 为可重建派生缓存，不属于必需备份；
- `.lifevault v3` 的媒体 inventory 使用仓库主密钥加密。
