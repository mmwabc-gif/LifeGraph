# LifeGraph v0.0.4.4 验收清单

## 目标

在 v0.0.4.3 的 `.lifevault` 导出、恢复演练和安全恢复基础上，建立本地自动备份、历史保留与管理闭环。

## 自动备份策略

- [ ] 个人设置中可启用或关闭本地自动备份；
- [ ] 可选择“每天”或“每周”；
- [ ] 可设置保留 3—50 个备份；
- [ ] 首次启用时立即创建一个已验证 `.lifevault`；
- [ ] 关闭自动备份后不再按周期生成，但已有历史保留；
- [ ] 即使策略关闭，也可点击“立即备份”生成本地历史版本。

## 到期触发

- [ ] 已启用且没有成功备份时，下一次正常 API 活动后生成备份；
- [ ] 未到周期时不会重复生成；
- [ ] 到期检查不在备份历史接口上触发，避免清空后立即重新生成；
- [ ] 自动备份失败不会让已经成功的内容保存、档案修改或页面读取变成失败；
- [ ] 失败状态会记录，至少等待一小时后再尝试。

## 历史管理

- [ ] 自动备份保存到 `data/backups/auto/`；
- [ ] 历史列表显示文件名、时间、大小、schema 和校验状态；
- [ ] 可下载单个自动备份；
- [ ] 可删除单个自动备份；
- [ ] 可二次确认后清空全部自动备份历史；
- [ ] 生成新备份后按保留数量自动删除最旧文件；
- [ ] 清理不触碰当前 `vault.json`、`lifegraph.db`、手动导出的备份或 `data/recovery/`。

## 完整性与安全

- [ ] 每个自动备份继续使用 SQLite Backup API 生成一致性快照；
- [ ] 生成前逐条验证加密档案和内容；
- [ ] 落盘后重新打开 `.lifevault` 校验结构与 SHA-256；
- [ ] 历史文件下载与删除要求有效会话；
- [ ] 文件名限制在自动备份目录内，不能使用路径穿越；
- [ ] 备份中不出现姓名、出生日期、标题、正文、PIN 或恢复凭据明文。

## 兼容性

- [ ] 原有未包含 `backup_policy` 的 `vault.json` 默认视为自动备份关闭；
- [ ] 数据库 schema 继续为 v3，无需迁移；
- [ ] v0.0.4.1—v0.0.4.3 的导出、演练和恢复接口继续工作；
- [ ] 首页与全页视图中的个人设置均可访问自动备份区域。
