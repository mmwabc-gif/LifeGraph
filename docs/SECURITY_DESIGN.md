# LifeGraph 安全设计（更新至 v0.0.4）

## 密钥分层

```text
PIN / 恢复密钥
      ↓ Argon2id
包装密钥
      ↓ AES-GCM
随机仓库主密钥
      ↓ AES-GCM
个人档案、事件、记忆与计划正文
```

## 已落实

- PIN 为 6—12 位数字；
- PIN 不直接充当业务数据密钥；
- 主密钥使用安全随机数生成；
- 恢复密钥与 PIN 使用不同盐和 AAD；
- AES-GCM 同时提供加密与完整性验证；
- 会话令牌仅保存在内存与浏览器 `sessionStorage`；
- 本地服务默认只监听 `127.0.0.1`；
- `data/`、数据库和 `.lifevault` 被 Git 忽略；
- 日志不输出 PIN、恢复密钥或主密钥；
- 修改 PIN 只重新包装同一个主密钥，不批量重写业务密文；
- 更换恢复密钥同样只重新包装恢复密钥槽，PIN 槽和业务密文保持不变；
- 恢复密钥轮换要求再次验证当前 PIN；
- 密钥槽摘要只显示 Argon2id 算法名称和更新时间；
- 安全审计只保存动作代码、成功结果和 UTC 时间戳，最多保留 50 条；
- `.lifevault` 导出前验证 SQLite、外键和全部加密记录；
- 导入先在临时目录完成恢复演练，正式替换前生成安全回滚包；
- 自动备份只保存加密仓库与完整性清单，不保存解密后的姓名或内容；
- 新自动备份在记录成功前重新读取落盘文件，并验证结构、校验和、SQLite、外键和全部密文；
- 最近备份快速验证只读取备份文件，不替换或修改当前仓库；
- 自动备份下载、删除和清空都要求有效解锁会话；
- 历史文件名经过目录边界校验，不能借助路径穿越访问其他文件。

## 恢复密钥轮换与审计

`vault.json` 中可以保存：

- `key_slot_updated_at.pin`：PIN 密钥槽最近包装时间；
- `key_slot_updated_at.recovery`：恢复密钥槽最近包装时间；
- `security_updated_at`：最近一次安全设置更新时间；
- `security_audit`：最多 50 条安全操作摘要。

审计记录不包含：

- PIN 或恢复密钥；
- 主密钥或包装密钥；
- 姓名、出生日期、标题或正文；
- 恢复密钥长度、片段或哈希。

更换恢复密钥后，原恢复密钥槽被原子替换，因此原凭据不能再解锁当前仓库。此前已经导出的 `.lifevault` 包含导出时的 `vault.json`，仍需使用导出当时的 PIN 或恢复密钥。

## 自动备份策略元数据

`vault.json` 中的 `backup_policy` 可以包含：

- 是否启用；
- 每天或每周周期；
- 保留数量；
- 最近尝试、成功与错误时间；
- 最近备份文件名和非敏感错误摘要；
- 最近完整验证时间、验证文件名和非敏感验证错误摘要。

该策略不包含姓名、出生日期、内容标题、正文、PIN、恢复密钥或主密钥明文。它随 `.lifevault` 一起迁移，使恢复后的仓库可以保留原自动备份偏好。

## 原型限制

- Python 无法保证主密钥内存被立即物理清零；
- 当前使用字段级加密，数据库表结构和时间索引仍可见；
- 尚未实现错误 PIN 的持久化限速；
- 尚未实现操作系统安全凭据存储；
- 本地自动备份仍位于同一设备，不能替代异盘或异地备份；
- 尚未经过第三方安全审计。
