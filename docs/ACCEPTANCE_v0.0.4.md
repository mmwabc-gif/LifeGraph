## 版本与启动

- [ ] 首页构建标识、`/health`、`/api/v1/system/status` 与 Python 包版本均为 `0.0.4`；
- [ ] `start.bat` 可完成首次初始化，`start_server_only.bat` 可停止旧进程并重新启动；
- [ ] 从 v0.0.3 覆盖升级后无需重新初始化仓库；
- [ ] 既有姓名、出生日期、内容、回收站和 PIN 可正常使用。

## `.lifevault` 导出与恢复

- [ ] 完整性检查可验证 SQLite、外键、档案和全部内容密文；
- [ ] 导出文件包含 `manifest.json`、`repository/vault.json` 和 `repository/lifegraph.db`；
- [ ] 清单文件大小与 SHA-256 与实际文件一致；
- [ ] 可使用备份生成时的 PIN 或恢复密钥执行恢复演练；
- [ ] 恢复演练不修改当前仓库；
- [ ] 正式恢复前自动生成 `data/recovery/` 安全备份；
- [ ] 正式恢复成功后撤销旧会话并要求重新解锁；
- [ ] 模拟替换失败时可自动回滚原仓库。

## 自动备份与健康状态

- [ ] 可启用或关闭每天／每周自动备份；
- [ ] 可设置保留 3—50 个历史备份；
- [ ] 启用时可立即生成首个备份；
- [ ] 到期后在正常 API 活动完成时补做备份；
- [ ] 可查看、下载、删除或清空自动备份历史；
- [ ] 保留数量清理不影响当前仓库或 `data/recovery/`；
- [ ] 健康状态可区分健康、待验证、超期、失败、损坏、无备份和未启用；
- [ ] 最近备份快速验证只读取文件，不替换当前仓库；
- [ ] 损坏 ZIP 或校验失败返回可读错误，不产生未处理异常。

## 安全设置

- [ ] 修改 PIN 后原 PIN 失效，新 PIN 可解锁，业务密文不变；
- [ ] 可使用恢复密钥重置 PIN；
- [ ] 可使用当前 PIN 更换恢复密钥；
- [ ] 更换后旧恢复密钥不能解锁当前仓库，当前 PIN 仍有效；
- [ ] 旧备份仍需使用其导出时的旧 PIN 或旧恢复密钥；
- [ ] 密钥槽摘要仅显示算法和更新时间；
- [ ] 安全审计不记录 PIN、恢复密钥、主密钥或私人正文。

## 个人设置界面

- [ ] 个人设置分为“个人档案／安全设置／备份与迁移”三组；
- [ ] 各组具有通栏标题、图标、边框和清晰留白；
- [ ] 恢复密钥修改位于安全设置；
- [ ] 打开设置时姓名和出生日期默认只读；
- [ ] 点击“编辑个人档案”后才出现表单和 PIN 确认；
- [ ] 取消编辑返回只读摘要并清除确认 PIN；
- [ ] 常规桌面窗口不超出底部；高度不足时内容可滚动且滚动条轨道隐藏。
